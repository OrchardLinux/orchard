# iPad mini 4 Wi-Fi (J96): RAM-boot bring-up record

This is a field report for the iPad mini 4 Wi-Fi (`iPad5,1`, J96, Apple
A8/T7000, 2 GB). It records experiments on one device between 30 October and
5 November 2026. It is not yet a device profile, kernel producer or firmware
recipe: the work ran on a local kernel tree, not on Orchard's build, so
`devices/j96` is unchanged. The values below are what a J96 profile needs.

## Measured on the device

## Touch

The panel is an N1 (iPadOS `AppleMultitouchN1SPI`, personality `C1F14,4`),
like the iPad 5 and iPad Air 2. `J96.mtprops` in the iPadOS 15.8.3 IPSW holds
a ready-made Z2 (HBPP) firmware blob of 58,812 bytes; the calibration comes
from the ADT (`multi-touch-calibration`, 1024 B; `prox-calibration`, 128 B).

- **Bus:** SPI1 (`0x20a084000`, AIC 153), 1 MHz, mode 3, chip select on GPIO 15.
  Transfers of at most 16 bytes, full duplex.
- **Pins:** IRQ GPIO 106 (active low), reset GPIO 56, LDO GPIO 47.
  `display_sync` (GPIO 78) was left alone.
- **Power-up, in iPadOS's order:**
  1. PMIC (D2207, I2C0 0x3c) ldo15 on: register `0x84` bits 0–2. Bits 0–1 are shared with two sibling outputs.
  2. LDO GPIO on, then 5 ms.
  3. Touch clock on: pmgr `+0x1e000`, divider `0x2dc` (32.768 kHz).
  4. 15 ms, then wake `19 c1` and 10 ms.
  5. S_CLK dummy transfer, reset release, then 30 ms.
  6. HBPP probe; it answered `1f 01 48 79 …`.
- **Bootload:**
  1. Prox calibration DATA at `0x10009600`.
  2. Calibration at `0x10009000`, in 1008-byte chunks.
  3. The firmware blob, as is.
  4. N1 version read at `0x10008ffc`. This unit returned `0x434d15c1`, so the const-cal value is 3.
  5. Register writes `0x10003060`←`0x17c9`, `0x1000305c`←`0x20`, `0x10003058`←6, `0x10003000`←3, `0x10003518`←1.
  6. APU read at `0x10003800`.
  7. `1f 01`, then 65 ms.
  8. EXECUTE at `0x10003400`.

  Every DATA and register write was acked (`4bc1`, `4ad1`) on the first try. The whole upload took 0.9 s.
- **Reports:** after the iPadOS wake command (`ee`, thirteen `00`, `ee 00`), upstream
  `apple_z2`'s `0xEB` interrupt-data read works unchanged: reply marker `e1`,
  finger count at message byte 16, 30-byte finger records at byte 24, states
  3 (start) and 4 (move). 1,543 of 1,543 reads were valid.
- **Axes:** raw x runs left to right (about 0–11,700) and raw y bottom to top
  (about 0–15,700). Values near the edges go slightly negative, so they are
  signed 16-bit.

## Wi-Fi

The J96 PCIe controller is the T7000 `apcie` with two ports. Only port 1 is
wired (`pci-bridge1`, Gen1), with the BCM4350 behind it. The ADT values match
the iPad Air 2 except for the sideband GPIOs:

- PERST# GPIO 77
- DEVICE_WAKE GPIO 63 (active high)
- CLKREQ# GPIO 41
- REG_ON on PMIC GPIO 3

The DART is at `0x602002000` (AIC 216). MSI uses AIC 224–255 with doorbell
`0xbffff000`.

Orchard's `pcie-apple-h9p` T7000 support brought the link up on the two-port
controller unchanged. Only the `apple,t8010-pcie` binding had to accept four
reg windows and two interrupts. With the Wi-Fi node disabled, the downstream
bus scan would run across a down link; a guard that checks DLLLA before
non-root config accesses avoids that.

This unit's chip is **BCM4350 rev 8 (C5)**, not the C2 the iPad Air 2 has. brcmfmac
requests `brcm/brcmfmac4350-pcie.apple,zinfandela`. The IPSW's C5 set
(`C-4350__s-C5/zinfandela.{trx,clmb,txcb}` and the `zinfandela` NVRAMs) worked,
installed as `.bin`, `.clm_blob` and `.txcap_blob`: firmware 7.64.133.15
(r936348) and the TxCap blob loaded. A J96 firmware recipe therefore needs the C5
outputs as well as C2/C4 (C2 and C4 share the `brcmfmac4350c2-pcie` prefix).

## Not done

Charging, audio, sensors, Touch ID, cameras, Bluetooth (BCM4350 BT core on
UART1), suspend, reboot and installed boot. No Apple firmware, calibration,
captured device tree or credentials are included here.

## Follow-up

The J96 device description has since been added from these values: the
`t7000-j96` device-tree patches for touch, battery, PCIe and Wi-Fi
(`kernel/patches/devices/t7000/0003`-`0006`), `C1F14,4` match data for
`apple_z2`'s N1 runtime, and a firmware recipe for `J96.mtprops` and the
`zinfandela` C2 and C5 sets. C2 and C4 share brcmfmac's `brcmfmac4350c2-pcie`
name and their files differ, so a C4 unit is not covered yet.

Still to do: re-test each feature on Orchard's build. Until then
`devices/j96/device.toml` lists touch, Wi-Fi and the battery gauge as
`untested`.
