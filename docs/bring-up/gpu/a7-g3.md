# A7 GPU (G3): Apple's data, the firmware boot, what comes next

The A7 (S5L8960X) has a PowerVR G6430, Apple's "G3". No Orchard code drove
it before this change. The J85 field report ([j85.md](../j85.md)) got as
far as one framework-owned GFX power transition on a private RAM image.
This page lists what Apple's own data says about the GPU, what the kernel
does with it, what was measured on a J71, and what is still open. Every value below comes from
Apple's restore images for the boards' own recipes (iOS 12.5.8, 16H88:
J71, J85 and N51; iOS 12.5.7, 16H81: J72) or from this repository. Nothing
else is assumed.

|---|---|---|

The GFX entry of the ADT's `pmgr` `devices` has no parent and lists bridges 11 and 12.

## Hardware (J71, 27 Nov 2026)

- With MISC_ACG set, `dwi` and `ps_gfx` on and Fender in state 1, the core
  reads CORE_REVISION `0x00014600` and CORE_ID `0x011b0403` (BVNC
  1.70.4.3, four clusters): a core AGXG3_B0 accepts. PMGR page 5 `+0x0`
  bit 30 rises with the wake (`0x00001010` to `0x44001010`); `+0x4` does
  not change.
- The live ADT's `bridge-settings` (one property: `(offset, value)` pairs
  per bridge, each list ended by `(0, 0)`) give bridge 11 `+0x14 =
  0x80010004` and bridge 12 the A8's 32 words; `sgx` `perf-states` are
  330, 390 and 450 MHz at 871, 937 and 1000 mV, and their halves (7 rows).
- The firmware boots to its alive event, takes an empty device-control
  command and survives runtime suspend and resume: nine boots and stops in
  a row, with the firmware's interrupt taken.
- At boot the firmware writes at GPU VA `0xff_ffff_fff0`; without a page
  there that is an MMU fault (bank 1, tag 3, context 0) and the firmware's
  lockup recovery at every boot. The driver maps a scratch page there; the
  firmware leaves it zero.
- Two things hung the SoC: reading PMGR page 5 with the GPU powered off
  after a firmware run, and switching `dwi` off right after a GPU
  power-down (on some cycles). The driver reads nothing of the GPU's with
  its domain off, and `dwi` is always on (Apple's ADT flags it as it flags
  the always-on AIC, GPIO and LIO).

## What the kernel does

OrchardLinux/linux#17, four commits: the binding, the GPU node (on for the
iPad Air, J71-J73), `ps_dwi` always on, and the driver.

- `apple,s5l8960x-gpu` has the A9's node shape plus the A8's `pmgr` and
  `bridges` registers.
- powervr boots the A7 with the A8's variant (`pvr_apple_s8003.c`,
  `struct t7000_soc`): AGXG3 runs AGXG4P's code nearly unchanged in the
  16H88 kernelcaches. The differences: the identity check and chip info,
  the CSC block at PLATFORM +0x38, the `_noastc` border table
  (`apple/gfx-s5l8960x-border.bin`), no FenceBuffer, no SLC setup in the
  boot stream, the J71's MHz/mV rows, the power state left to the power
  domain, the bridge values above, the PLL lock as page 5 `+0x0` bit 30,
  the scratch page, and the empty device-control command after the alive
  event.
- BVNC 1.70.4.3 is experimental: `powervr.exp_hw_support=1`.
- debugfs `apple_start` starts the firmware without a job (for testing
  power cycles).

## Userspace

OrchardLinux/mesa#20 (`a7/vulkan`): the A7 device entry and a compute-only
Vulkan driver whose shaders use the A7's Rogue encoding with its measured
differences (a store takes its data from the registers after its address
pair; a 2-byte upper-source form; no 4-byte stores). On a J71: vulkaninfo,
vkCreateDevice and ten compute rungs pass, up to 2048 workgroups, every
buffer checked on the CPU.

## Open

1. Shaders beyond stores: Apple's A7 backend (`agx0`) is Rogue, not the
   A8-A10 Apple ISA (`agx1`), so upstream pco is the base, with the A7's
   differences. Coefficient (common store) inputs wedged the firmware once.
2. The A7's TA/3D command layout: AGXG3 has its own 3D-channel HAL source
   (`agxk_hal_g3_b0_3d_channel.cpp`), so it may differ from the A8's.
3. The MHz/mV rows are the J71's; the other A7 boards' live ADTs were not
   read, so their GPU nodes stay off.
